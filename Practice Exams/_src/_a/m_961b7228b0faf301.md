(a) Look up the virtual page number in the TLB (associative match, possibly with ASID); hit → frame number + offset gives the physical address; miss → walk the page table, load the entry into the TLB, then retry\
(b) 1. `0xF12C`; 2. `0x2A9D`; 3. page 11 invalid → page fault\
(c) Multi-level (hierarchical) page tables, hashed page tables, inverted page tables, and larger pages (huge pages)\
(d) Kernel page-table isolation (KPTI/KAISER): unmap kernel memory from user page tables and switch page tables on every user/kernel transition; costs TLB flushes/CR3 switches, so syscall- and interrupt-heavy workloads slow down (mitigated by PCID)\
(e) Trap/syscall instruction → CPU switches to kernel mode, saves user state, jumps to handler via syscall table, executes, restores state and returns to user mode; `getpid()` is a system call, so yes, it requires a mode switch (unless cached/vDSO)
