(a) Kernel-buffered I/O: device $\to$ kernel buffer $\to$ application, two data transfers (one DMA, one CPU copy). Direct/unbuffered I/O: device $\to$ application, one DMA transfer and no intervening CPU copy. [?] If “buffered/unbuffered libraries” means stdio versus read/write, both use the page cache; stdio adds a user-space buffer, giving two versus one CPU copies instead.\
(b)(i) Sequential access within each file: higher streaming throughput and fewer seeks; requests for different files may be interleaved.\
(b)(ii) Blocking synchronous I/O waits until completion; nonblocking asynchronous I/O submits work and returns, reporting completion later. Choose asynchronous I/O with completion notifications to overlap disk/network operations and avoid busy polling.
