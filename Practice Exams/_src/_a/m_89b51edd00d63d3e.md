(a) `fork`: separate virtual address spaces, initially identical (usually copy-on-write), independently schedulable; ordinary memory writes are private, while inherited descriptors share open-file descriptions. `vfork`: child temporarily shares the parent's address space/stack, and the parent is suspended until child `exec`/`_exit`; use only for immediate `exec`/`_exit`, not general request handling.\
(b) One-to-one: each user thread maps to a kernel thread. Many-to-many: a user runtime multiplexes many user threads over a pool of kernel threads, allowing parallelism without a kernel thread for every user thread.
